# 独立系统的验收标准

本文件从零定义真实系统测试，不引用任何历史实验代号，也不要求模拟器存在。测试 ID、文件名和代码组织由实现者自行确定。每项报告通过、失败或未验证，并关联原始证据；替代硬件路径通过不等于目标路径通过。

## 1. 部署和路径

| 必须证明的内容 | 最小证据 |
| --- | --- |
| 环境可重建 | 上游 URL/tag/完整 SHA、扩展代码或 diff、安装构建命令、依赖锁、模型/tokenizer、实际模块/二进制路径和配置 |
| 真实 CXL backing | 设备/内存区域归属、NUMA/PCIe/CXL 拓扑及实际 buffer 归属；不能仅看命名 |
| CXL payload 直接进入 HBM | 实际执行的 API/调用链、源/目标内存归属、内容往返；排除普通 DRAM payload 暂存及上层缓存命中 |
| 可独立运行 | 新进程能启动、发请求、采集结果、停止；不需要其他项目、模拟器、个人技能或历史日志 |

CPU DRAM 控制结构不是被禁止的 payload 暂存。若原生 GPU/CXL 直达不可用，需明确缺少的硬件/驱动能力和已验证替代路线；不得把人为延时仿真当成物理 profile。

## 2. 功能场景

| 场景 | 需要核查 |
| --- | --- |
| 全 miss | 正常 prefill/decode；真实生成输出，建立可追踪 KV 身份 |
| HBM 命中 | 复用对应前缀，实际计算与复制计数吻合 |
| DRAM 恢复 | HBM 已无该对象，目录指向 DRAM，真实读取并在完成可见后计算 |
| CXL 恢复 | HBM 无对象且 DRAM 无该版本副本；目录、数据读取来源和实际字节证明 CXL 路径 |
| 回收后再访 | 保存、完成发布、释放 HBM、重用物理块、再次恢复的顺序合法 |
| 部分共享与多读者 | 前缀边界、多个读者和容量不重复计数；不同内容/版本不串用 |
| 在途冲突 | STORE 源保护、LOAD 目标预约、不可提前发布/复用；等待中的需求不反复制造多余写回 |
| 取消/复制失败 | 已提交操作安全完成或明确失败，清理引用和预约，不发布错误或部分内容 |
| 请求结束 | 已提交复制 drain，held blocks 和临时引用释放；保留缓存与 allocator backing 单独记账 |

复制前后对已定义 KV 区域做独立内容校验；padding 未定义区不作为有效数据比较。在固定可控推理条件下，对“重算”和“恢复”比较输出或 logits，提前定义数值容差，并区分批次导致的浮点变化。调试内容校验可额外同步，但相关计时不能冒充正常性能路径。

所有不变量在正常流程及失败流程都成立：
- 不超过各池物理可用容量；逻辑引用、临时副本、预约和真实占用分开。
- 读者或复制未释放前，源不能被覆盖。
- 完成且可见前，目标不能被声明 READY。
- 同一 KV 版本在 DRAM/CXL 间仅一个稳定归属；HBM 副本合法。
- 无重复发布、死锁、残留 writer/reader/transfer reservation。空闲后仍保留的合法缓存不算泄漏。
- 策略不读取未来到达或尚未发生的实际输出长度。

## 3. 最小工作负载和对照

由本项目生成输入，冻结实际文本/token、种子、根到达、输出预算和思考时间：
1. 无复用：观察框架/计算基础成本。
2. 固定前缀、多后缀及重复访问：明确区分 HBM/DRAM/CXL 恢复。
3. 保留竞争：先测活动/保护/预约峰值，选择能容纳当前活动请求但不能保留所有闲置内容的容量。报告活动容量等待，不能把它误叫作放置等待。
4. 小并发、短突发、空闲后重访：观察传输排队、批处理和主机唤醒影响。

HBM-only、HBM+DRAM、hybrid 使用相同引擎/模型/HBM 预算与推理设置。首轮只做小规模、可解释的机制探针；数量由现场时长决定，运行前写明数量、容量及超时。关闭策略的特殊测试钩子后，还要在正常路径跑通一次完整轻量服务负载。

比较需要区分两种问题：
- 固定 DRAM，再增加 CXL：容量扩展的综合效果。
- 相同总保留容量：路径/放置差异。若硬件无法提供等容量 DRAM 对照，标注该比较未做。
测试钩子可以强制保存位置和冷缓存以验证分支，不能把强制路径结果当正常策略效果。

## 4. 事件与成本交付契约

机器可读格式由实现者选取，需在项目说明中定义字段、单位、可空原因和版本，至少覆盖：

| 数据 | 必须保留的信息 |
| --- | --- |
| 环境/配置 | 硬件、软件 SHA、模型/layout、block/chunk 大小、实际池容量、batch/token 限额、并发、冷暖状态、观测开关 |
| 请求 | 请求/会话 ID、实际输入 token/hash、计划与实际到达、engine 入队、首次计算、首个非空输出、完成、失败/取消 |
| KV/传输 | 内容版本/前缀身份、物理 block/chunk/slot、源/目标介质、有效/实际字节、片段数、预约/pin、提交/DMA/观察/采纳/发布/释放、阻塞依赖 |
| 计算 | batch/step 关联、prefill/decode 形状、上下文长度、实际重算和可识别 GPU 区间 |
| 原语样本 | 操作、形状、方向、布局、并发集合、冷暖、时间基准、样本/重复数、服务时间分布 |
| 结果 | 平均/p95 TTFT、TPOT/ITL 的具体定义、完成时长/吞吐、失败；各层命中分母、传输次数/字节、实际 prefill/recompute、等待和占用峰值 |

不是要求新实现必须使用上述字面事件名，而是需要覆盖这些语义，并提供机器可解析的关联。

时间解释必须区分：
请求恢复需求产生 → 等待资源 → CPU 提交 → 设备实际搬运 → 完成被观察 → 调度器采纳 → 计算使用。
能定位关键依赖，不能把整段延迟算成 DMA；并发阶段按实际重叠记录，不能全部串行相加。无法采集的边界显式为空或记为区间估计，不伪造精确时间。

尽量量化 lookup/hash、分配/触页/注册、IPC、策略决策、gather/scatter、CPU 提交/同步/轮询、DMA、发布、推理与输出费用。分不开的开销给出包含关系；未测项和外推范围列出。trace-off 重复性能与轻量/重 profiler 结果分开，报告观测扰动。

## 5. 完成判定

必须具备：
- 正式 release 底座与独立扩展可复建。
- 目标路径有硬件/内容证据；功能场景和不变量通过。
- 小工作负载能完整结束，数据能追溯到实际事件，成功/失败请求都留存。
- 性能对照默认3次独立进程重复，保留波动；同向/双向/计算复制竞争至少有代表性样本。
- 原语测量有原始样本、覆盖表及独立留出检查，不能按最终 TTFT/策略名次拟合。
- 原始输入/事件/profile、生成/运行/分析入口与报告齐全，新进程按说明可以复跑。

发布前对关键测试重新运行；如果修改使旧测量失效，重新标注或补测受影响范围。功能失败必须修复或列为未通过；未验证项不能由“服务能启动”替代。

本轮不承诺任意 workload 的误差阈值、跨硬件泛化、算法优越性或已完成模拟器校准。若将来做预测误差/排序验证，应在独立验证前冻结比较协议；目前只需让数据和语义足以被其他模拟器消费。
